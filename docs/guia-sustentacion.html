1. Resumen del proyecto

Se construyó una API REST para administrar facultades y sus estudiantes usando el modelo 1:N con documentos embebidos de MongoDB. No existe una colección independiente de estudiantes: cada estudiante vive dentro del arreglo estudiantes de su facultad. La API implementa el CRUD completo, listados paginados, tres validaciones, limpieza de espacios (trim) y soporte para tildes y ñ.

2. Modelo 1:N embebido

Una facultad contiene muchos estudiantes. En MongoDB esto se representa con un arreglo de subdocumentos dentro del mismo documento. La relación se lee completa en una sola consulta, sin $lookup ni JOIN. 

{
  "_id": ObjectId("6b0354700d92622fc59b4034"),
  "nombre": "Ingeniería de Sistemas",
  "codigo": "ING-SIS",
  "estudiantes": [
    {
      "_id": ObjectId("..."),
      "nombre": "José Ñáñez",
      "email": "jose.nanez@correo.com",
      "edad": 20,
      "semestre": 4,
      "creadoEn": ISODate("...")
    },
    {
      "_id": ObjectId("..."),
      "nombre": "María Peña",
      "email": "maria.pena@correo.com",
      "edad": 21,
      "semestre": 5
    }
  ],
  "creadoEn": ISODate("...")
}
OperaciónOperador MongoDBEfecto
Agregar estudiante$push: { estudiantes: nuevo }Inserta al final del arreglo
Actualizar estudiante$set: { "estudiantes.$.nombre": ... }El operador $ apunta al subdocumento encontrado
Eliminar estudiante$pull: { estudiantes: { _id } }Saca el subdocumento del arreglo
Eliminar facultaddeleteOne({ _id })Borra también sus estudiantes (cascada)
Paginar embebidos$slice: ['$estudiantes', saltar, limite]Trae solo el tramo de la página
¿Por qué embeber y no referenciar? Los estudiantes siempre se consultan junto con su facultad y no se comparten entre facultades. Embeber evita un $lookup, simplifica el borrado en cascada y permite leer todo en una sola operación. La desventaja es el límite de 16 MB por documento y que no sirve si los datos crecen demasiado o se comparten.

4. Endpoint solicitado: agregar 1 registro embebido

El enunciado pide POST /courses/:id/students. En este dominio, "course" es la facultad y "student" es el estudiante, por lo que el endpoint equivalente es:

POST /api/facultades/:id/estudiantes
Agrega un estudiante al arreglo embebido de la facultad indicada en la URL.

Petición

curl -X POST "http://localhost:3000/api/facultades/$FACULTAD_ID/estudiantes" \
  -H "Content-Type: application/json" \
  -d '{
    "nombre": "  Ana   María   Peñaranda  ",
    "email": "  ANA.PENARANDA@Correo.com  ",
    "edad": 21,
    "semestre": 6
  }'

Respuesta real de la API (201 Created)

{
  "mensaje": "Estudiante agregado al arreglo embebido de la facultad.",
  "data": {
    "_id": "6b04e2215d6577d015a7f7d4",
    "nombre": "Ana María Peñaranda",
    "email": "ana.penaranda@correo.com",
    "edad": 21,
    "semestre": 6,
    "creadoEn": "2026-11-24T01:02:25.997Z",
    "facultad": {
      "_id": "6b0354700d92622fc59b4034",
      "nombre": "Ingeniería de Sistemas",
      "codigo": "ING-SIS"
    }
  },
  "totalEstudiantes": 4
}

Observe que el trim dejó "Ana María Peñaranda", el email se normalizó a minúsculas y el campo facultadId no se envía en el cuerpo: se toma del :id de la URL.

5. Paginación

Todos los listados reciben page y limit. El límite por defecto es 5 y el máximo 50. La respuesta siempre incluye pagina, limite, total y totalPaginas para que el cliente sepa cuántas páginas existen. 

GET /api/facultades?page=1&limit=2
{
  "data": [
    { "codigo": "ADMON", "nombre": "Administración de Empresas", "totalEstudiantes": 1 },
    { "codigo": "SALUD", "nombre": "Ciencias de la Salud", "totalEstudiantes": 2 }
  ],
  "paginacion": { "pagina": 1, "limite": 2, "total": 3, "totalPaginas": 2 }
}
ListadoCómo pagina
GET /api/facultades$skip + $limit sobre la colección
GET /api/facultades/:id/estudiantes$slice sobre el arreglo embebido
GET /api/estudiantesLista plana ordenada en español + slice

En /api/facultades el listado no devuelve el arreglo completo, solo su tamaño (totalEstudiantes), para que la respuesta sea liviana.

Trim centralizado

function limpiarTexto(valor) {
  if (typeof valor !== "string") return "";
  return valor.trim().replace(/\s+/g, " ");
}
// "  José   Ñáñez  "  ->  "José Ñáñez"

trim() quita espacios al inicio y al final; el reemplazo deja un solo espacio entre palabras. El email se pasa a minúsculas y el código de facultad a mayúsculas.

Tildes y ñ

const REGEX_NOMBRE = /^[\p{L}\s]+$/u;

\p{L} significa cualquier letra Unicode, así que acepta á é í ó ú ü ñ y letras de otros idiomas. La bandera u activa el modo Unicode. MongoDB guarda UTF-8, por lo que José Ñáñez se conserva tal cual; además los listados ordenan en español con collation y localeCompare("es").

8. Demo para la sustentación (paso a paso)

  1. Verificar MongoDB: mongosh --quiet --eval "db.runCommand({ ping: 1 })"
  2. Instalar y arrancar: npm install y npm start
  3. Abrir la ayuda: curl http://localhost:3000/api
  4. Listar facultades paginadas: curl "http://localhost:3000/api/facultades?page=1&limit=2"
  5. Guardar el id de una facultad en FACULTAD_ID.
  6. Agregar un estudiante embebido con el endpoint de la sección 4.
  7. Ver la facultad completa: curl "http://localhost:3000/api/facultades/$FACULTAD_ID"
  8. Paginar sus estudiantes: curl ".../estudiantes?page=1&limit=2"
  9. Actualizar y eliminar el estudiante con PUT y DELETE.
  10. Mostrar en MongoDB Compass la base estudiantes_facultades y la colección facultades.
Recuerda tener MongoDB corriendo antes de npm start. Al primer arranque se crean 3 facultades de ejemplo con 6 estudiantes embebidos.

11. Posibles preguntas del profesor

PreguntaRespuesta corta
¿Dónde está la relación 1:N?En el arreglo estudiantes dentro de cada documento de facultades: una facultad tiene muchos estudiantes y cada estudiante vive en una sola facultad.
¿Por qué no hay colección de estudiantes?Porque el modelo es embebido: los estudiantes son subdocumentos. Así se leen con la facultad en una sola consulta y se eliminan en cascada.
¿Cómo se agrega un estudiante?Con $push al arreglo embebido, en POST /api/facultades/:id/estudiantes.
¿Cómo se actualiza un embebido?Con $set y el operador posicional $, que apunta al subdocumento encontrado.
¿Cómo se elimina?Con $pull para sacarlo del arreglo; si se elimina la facultad, se borran todos sus estudiantes.
¿Cómo se pagina el arreglo embebido?Con $slice, que trae solo el tramo de la página, sin cargar todo el arreglo.
¿Cómo se evita un email repetido?Consultando { "estudiantes.email": email } antes de insertar o actualizar y respondiendo 409.
¿Por qué no hay índice único en el email?Porque está dentro de un arreglo; el índice único se usa para el código de facultad y la unicidad del email se valida en código.
¿Qué pasa con los 16 MB?Es el límite por documento. Embeber sirve aquí porque los estudiantes son pocos y no se comparten; si creciera demasiado se usaría referencias.
¿Qué hace el trim y qué pasa con la ñ?Quita espacios sobrantes y normaliza; la regex Unicode \p{L} acepta tildes y ñ sin problema.

npm start

# 4. Probar

Variables opcionales: PORT (3000), MONGODB_URI (mongodb://127.0.0.1:27017) y MONGODB_DB (estudiantes_facultades). El README del repositorio contiene todos los comandos curl y la tabla completa de endpoints.
